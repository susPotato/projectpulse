### 17 - Published pages were unstyled and chartless
The local server and the published site looked completely different, and the published
one was right to be suspected.
- **Root cause:** the pages link `/static/shell.css`; the publisher wrote
  `site/shell.css`. **Cloudflare Pages answers an unmatched path with `index.html` and
  status 200**, so `/static/shell.css` returned 22,675 bytes of `text/html`. Every status
  check I had run passed. The browser refused HTML as a stylesheet -> unstyled pages;
  `gantt.js` was HTML too -> `PulseGantt` never defined -> no chart; and the driving-path
  labels went white-on-white because an inline `color:#fff` applied while the `--navy`
  behind it no longer resolved.
- **Fixed** by deriving each destination from the reference: `publish._referenced_assets`
  reads the `href`/`src` URLs out of the pages and copies each asset to that exact path,
  so the two cannot disagree. `_verify` then fails the build if a referenced asset is
  missing - a silent 200 is not something a human catches by looking.
- **Also fixed** the `+34d` label on the longest bar being clipped by the plot edge: it
  now flips inside the bar with a light fill. The worst slip on the chart was the one
  figure that could not be read.
- **Lesson recorded:** verify a deploy by `content_type`, never by status code.

### 16 - Fixed `PulseGantt is not defined`
- **Root cause:** `gantt.js` is loaded with `defer`, so it executes after the document is
  parsed; the inline script executes *during* parsing and starts its fetch immediately.
  Normally the network is slower than the remaining parse - but a **cached** response is
  not, and the published snapshot sets `Cache-Control: max-age=300`. So the data arrived
  before the chart component existed.
- **Fixed** by gating render on `documentReady()` in both `gantt.html` and `explain.html`,
  which removes the race rather than relying on the network being slow.
- **Also fixed a second defect the first one exposed:** the `ReferenceError` was thrown
  inside `render`, which sat in the fetch promise chain, so the fetch's `.catch` reported
  it as "Could not reach the server" - sending a reader to the network when the server had
  answered fine. The network `.catch` now precedes the render step, and render has its own
  handler and message.
- **Added** an explicit `typeof PulseGantt === "undefined"` check that names the missing
  component, and made the Calculation tab drop the chart rather than the page.
- **Reproduced and verified** with a node harness that resolves the fetch instantly while
  holding the deferred script back: gate present -> chart drawn; gate removed -> not drawn.
